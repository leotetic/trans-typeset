# Web 前端商业化上线优化计划

## 当前定位

`apps/web` 是一个本地 PDF 翻译排版工作台，第一屏必须直接可用：上传 PDF、选择目标语言、查看任务进度、预览译文、下载 PDF。上线前端目标不是做营销页，而是把核心流程做得稳定、清晰、可恢复。

## 已落地的前端上线项

- 核心工作流：PDF 选择、目标语言、任务提交、状态轮询、预览 iframe、PDF 下载。
- 状态覆盖：`queued`、`parsing`、`translating`、`rendering`、`completed`、`failed`。
- 响应式布局：桌面左右分栏，移动端上下布局。
- 文件体验：文件名、大小、非 PDF 反馈，长文本防溢出。
- 产品韧性：后端错误展示、状态读取失败提示、运行时响应字段校验、可手动重试读取状态。
- 可访问性基础：语义分区、表单标签、进度条 ARIA、键盘可触达上传入口。

## 上线前必须通过的门禁

- `npm run typecheck:web`
- `npm run build:web`
- 桌面 1280px：控制区在左，预览区在右，首屏直接可操作。
- 移动 390px：控制区在上，预览区在下，无横向溢出。
- 上传非 PDF：不提交请求，并展示明确错误。
- 后端 4xx/5xx：展示 `detail`、`error` 或 `message`，保留用户可恢复路径。
- 任务完成：iframe 指向 `/api/documents/{doc_id}/preview`，下载指向 `/api/documents/{doc_id}/download`。

## 下一阶段建议

- 接入真实鉴权与配额后，在前端显示剩余任务额度和文件限制。
- 增加任务历史列表，让用户回到最近完成的文档。
- 增加预览失败兜底，例如直接打开预览和重新生成提示。
- 增加轻量埋点，仅记录状态耗时和错误类型，不记录文档内容。
- 用端到端测试覆盖上传、轮询成功、轮询失败、完成下载四条路径。
- 接入错误监控和构建产物部署检查，形成发布前自动门禁。
